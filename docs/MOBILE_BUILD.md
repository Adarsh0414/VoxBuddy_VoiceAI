# Building VoxBuddy for Android + iOS

## Current status

**Android: real, built, installed, and tested on a physical device** — not
just a generated scaffold anymore. `mobile/android` is a working Android
Studio/Gradle project (`com.voxbuddy.app`) with real native code on top of
the Capacitor shell:

- `AudioDevicePlugin.java` — detects an already-connected Bluetooth Classic
  (A2DP) audio device (most real earbuds/neckbands, as opposed to BLE-only
  accessories) so the app knows earbud audio routing is live without
  needing a separate scan
- `ConversationForegroundService.java` + `ConversationServicePlugin.java` —
  keeps microphone capture alive when the app is backgrounded (phone in
  pocket, screen off), which is the whole point of a hands-free product
- Adaptive launcher icons regenerated for real, all density buckets
  (`mipmap-ldpi` through `mipmap-xxxhdpi`)
- Real permissions declared in `AndroidManifest.xml`: `RECORD_AUDIO`,
  `BLUETOOTH_CONNECT`/`BLUETOOTH_SCAN` (with `neverForLocation` on modern
  Android), `FOREGROUND_SERVICE_MICROPHONE`, `POST_NOTIFICATIONS`,
  `WAKE_LOCK`
- `voxbuddy://auth` deep link wired for the native Google Sign-In flow
  (Google's JS SDK can't run inside an embedded WebView, so native uses a
  real authorization-code exchange instead — see `backend/app.py`'s
  `/api/auth/google/callback`)

**iOS: scaffolded only** — a real Xcode project exists at `mobile/ios`
(generated by Capacitor's own CLI, with a full icon/splash asset set), but
it has not been opened, built, or run, because that fundamentally requires
a Mac with Xcode. No framework — Capacitor, React Native, Flutter, or
hand-written Swift — can get around that Apple platform requirement.

## What's in `mobile/`

```
mobile/
  capacitor.config.ts   <- points the native shell at your deployed backend
  android/               <- real Android Studio / Gradle project (built + tested)
    app/src/main/java/com/voxbuddy/app/
      AudioDevicePlugin.java
      ConversationForegroundService.java
      ConversationServicePlugin.java
      MainActivity.java          <- registers both plugins
  ios/                    <- real Xcode project (generated, not yet built)
  resources/              <- source icon/splash images
  www/                    <- placeholder Capacitor's CLI requires; unused,
                              see the note in capacitor.config.ts
```

## Point it at your real backend before building

`mobile/capacitor.config.ts` already points at the deployed Render backend:

```ts
server: {
  url: 'https://voxbuddy-backend.onrender.com/app',
  cleartext: false,
}
```

VoxBuddy has nothing meaningful to show until this points at a live
server — there's no offline-first bundle, the native shell is a thin
wrapper around the real backend's `/app` page. If you redeploy to a
different URL, update this and resync:

```bash
cd mobile
npm install
npx cap sync android
```

## Android — building and installing on your own device

This is the tested, working path:

1. `cd mobile && npx cap sync android` after any change to `frontend/`,
   `capacitor.config.ts`, or the native Java files above
2. Open the `mobile/android` folder in Android Studio and let Gradle sync
3. Run on a physical device over USB (Settings → About phone → tap Build
   Number 7 times to enable Developer Options → enable USB debugging) or
   an emulator
4. When ready to publish: Build → Generate Signed Bundle/APK, following
   Android Studio's own signing wizard — **back up that signing key
   somewhere safe**, losing it means you can never update this app
   listing again
5. Continue from Step 5 of `docs/PLAY_STORE_PUBLISHING.md`

Real bugs already caught and fixed through this real-device testing loop
(see `PROGRESS.md` for full detail on each): a stale service-worker cache
serving old content after deploys, a Classic-Bluetooth-vs-BLE mismatch
that made a real neckband invisible to the original scan-only detection
logic, a MIUI-specific status bar rendering artifact, and a WAKE_LOCK
crash. This is the actual value of testing on real hardware instead of
only reasoning about the code — none of these would show up in the
backend's unit test suite.

## iOS — needs a Mac with Xcode (not started)

1. Copy (or clone) this repo onto a Mac
2. Install [Xcode](https://apps.apple.com/us/app/xcode/id497799835) from
   the Mac App Store (free)
3. Install [CocoaPods](https://cocoapods.org): `sudo gem install cocoapods`
4. `cd mobile/ios/App && pod install`
5. Open `App.xcworkspace` (not `.xcodeproj` — important, Capacitor apps
   need the workspace file since CocoaPods is involved) in Xcode
6. Run on the iOS Simulator or your own iPhone to test
7. To publish: you'll need an [Apple Developer account](https://developer.apple.com/programs/)
   ($99/year), then Xcode's Product → Archive → Distribute App flow,
   uploading to App Store Connect

Note: the native plugins above (`AudioDevicePlugin`, `ConversationForegroundService`)
are Android-only Java code — an iOS equivalent (Swift, using
`AVAudioSession`/background audio modes) would need to be written
separately when this is picked up.

If you don't have access to a Mac: a friend/colleague's Mac, a cloud Mac
rental service (MacStadium, MacinCloud), or a CI service with macOS
runners (GitHub Actions has macOS runners available) are the usual
options. Verify current pricing/terms before committing to one.

## Known gaps in the native layer

- **Real BLE pairing UI** — the in-app "Connect earbuds" scan screen
  still uses a simulated animation on the branches where real BLE isn't
  wired in; `AudioDevicePlugin` only *detects* an already-OS-paired
  Classic Bluetooth device, it doesn't drive the pairing flow itself.
  Translated audio already plays correctly through any already-connected
  earbud via normal OS audio routing regardless — this only affects the
  in-app status indicator, not actual functionality.
- **iOS has no native plugin work at all yet** — see above.
